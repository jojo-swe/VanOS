# Changelog

## Unreleased

### Fixed

- `GET /api/dashboard` stays up when the data disk is full. A filesystem write that fails with `ENOSPC`, `EDQUOT`, `EROFS`, `EACCES`, or another write error is logged once (the error code only) and does not crash the process. Reads keep serving the last good data with `degraded: true` and `reason` set to that code. If nothing can be served, the route answers `503` `{ "status": "degraded", "reason" }`.

### Security

- README screenshots of Mission Control are recaptured from demo mode (`VANOS_DEMO_MODE=true`, sample data only). The copyright line no longer uses a legal name.
- Deployment docs, the setup panel, and the landing page no longer name a VPS or n8n vendor. They say "your VPS" and "your n8n host". The privacy guard blocks those vendor names.
- `agents-backup/` is no longer in the repo. The backup script still keeps a local copy of each agent workspace there, but the folder is gitignored and `scripts/privacy-guard.sh` blocks it. The guard now also blocks `SOUL.md`, `USER.md`, `MEMORY.md` and `memory/` at any depth, not only at the root.
- `devin.yml` runs only on `workflow_dispatch` (no `pull_request_target`). `ci.yml` has `permissions: contents: read`. The secret scan covers the full git history. `export-ai-support-bundle.yml` is removed.
- Script paths are generic (`$OPENCLAW_HOME`, `VANOS_AGENTS_DIR`, `VANOS_WORKSPACE`), and the demo seeds in `ai-support` use neutral sample data only.

### Changed

- `.backup-to-github.sh` reads its paths from the environment: `OPENCLAW_HOME` (default `$HOME/.openclaw`), `VANOS_WORKSPACE` (default `$OPENCLAW_HOME/workspace`), `VANOS_AGENTS_DIR` (default `$OPENCLAW_HOME/agents`) and `VANOS_LOCAL_BACKUP_DIR` (default `$OPENCLAW_HOME/backups/main-agent`), so it runs both in the Docker image and in a native WSL install. It refuses to run on any branch other than `main`, stops when `scripts/privacy-guard.sh` is missing or fails, and pushes only `refs/heads/main`.

### Added

- The main agent's `SOUL.md`, `USER.md`, `MEMORY.md` and `memory/` are local-only: gitignored and blocked in CI by `scripts/privacy-guard.sh`. `.backup-to-github.sh` now keeps them as local tarballs instead (`VANOS_LOCAL_BACKUP_DIR`, newest 30 kept) and runs the privacy guard before every commit. Keep an off-machine copy of those tarballs. The history before this lives in the archived `jojo-swe/VanOS-old-history`.
- `scripts/move-workspace-to-new-history.sh`: a one-time move of the live OpenClaw workspace onto the new history. It saves the personal files first, keeps the old history as a local `old-history` branch, updates files the agents did not touch and keeps the ones they did. Run it once before the next backup, or that backup's push is rejected.
- `ai-support/BOARD-PROMPT.md`: a paste-ready instruction that has Muddy send the daily `board` report (agent status, crons, content, social, income, KPIs, schedule, system) so the Overview fills with real data.
- Money actions can be undone: a row changed from the dashboard shows **Undo**, which puts back the previous values (one step) via `POST /api/money/action` with `"action": "undo"`. Only trial and cancel-soon subscriptions get a **Mark cancelled** button; the others have a quiet "Cancel…" link.
- Outside the public demo, Mission Control shows only real data. Sections that used sample values (agent status, cron jobs, content, social, income, life, KPIs, schedule, system, the vanlife bar, sample alerts such as "Radar intel cron failing", sample mail, repos, money rows and cost history) are empty with "No … reported yet" until an agent sends them. Agents report the Overview sections with the new `board` ingest domain (`POST /api/v1/ingest` or a sync digest); see `ai-support/AGENT-API.md`. The MRR tile is the sum of reported income, unreported agents show as idle, and services that are not connected are a note instead of a warning. **After updating, the Overview looks empty until your agents report.**
- Exchange rates update themselves: Mission Control fetches Riksbanken's daily USD and EUR mid rates (public SWEA API, no key), stores them and refreshes about twice a day in the background, so a page never waits on Riksbanken and a failed fetch keeps the last good rates. Per currency, `MONEY_USD_SEK_RATE` / `MONEY_EUR_SEK_RATE` in env always win; otherwise the newer of an agent's rate and Riksbanken's wins; otherwise the defaults. The Money panel says where the rates came from ("from Riksbanken, 2026-10-16"), and `fxSource` gains `riksbank` plus `riksbankDate` and `fxSources`. Off in the demo; `MONEY_FX_AUTO=off` turns it off. Agent rates now record when they were sent; rates stored before this carry no time and give way to Riksbanken's. See `ai-support/AGENT-API.md`.
- Pick the currency Mission Control shows money in: **SEK** (default), **USD** or **EUR**, in the header or the phone menu. Costs, Money, Income and the Overview tiles convert to it; a money row kept in another currency also shows its own amount ("129 kr · $12.00"). The choice is stored per browser. Exchange rates come from `MONEY_USD_SEK_RATE` / `MONEY_EUR_SEK_RATE`, a money ingest (`usdToSek`, `eurToSek`) or Riksbanken (see above), else defaults, and the Money panel shows which rates are in use. Euro amounts were converted with a rough guess (about 9.7 kr per euro); they now use `eurToSek`.
- Money quick actions: **Mark paid** on unpaid bills, **Mark cancelled** on subscriptions (with a confirm step), **Mark sold** and **Mark paid** on items for sale. Each row shows the result inline. They post to `POST /api/money/action` (dashboard auth, same-origin JSON, private only, off in the demo). Changed rows record `paidAt`, `cancelledAt`, `soldAt` and `dashboardChange` so agents see them on their next read, and a stale agent ingest no longer undoes them; send `dashboardChange: null` to override. Subscriptions gain a `cancelled` status. See `ai-support/AGENT-API.md`.
- On phones (below `md`), the Costs line items and the Money subscriptions and sale tables collapse to compact two-line rows instead of one tall card per field. From `md` up the tables are unchanged.

- Slack support. **Notifications**: set `SLACK_WEBHOOK_URL` (an incoming webhook on hooks.slack.com) and Mission Control posts bot errors, error heartbeats and alerts, and dispatches a bot did not accept; `SLACK_NOTIFY=all` adds finished results, `off` mutes it. Notices are deduplicated for 10 minutes, capped at 20 a minute, escaped so bots cannot ping `@channel`, and sent in the background so Slack never slows ingest. **Panel**: `SLACK_BOT_TOKEN` plus `SLACK_CHANNEL_IDS` show the latest messages per channel on the Integrations panel (`GET /api/slack`, agents `GET /api/v1/slack`), read-only. **Connection**: Slack is listed under Connections and agents can report its status through connections ingest. See `ai-support/INTEGRATIONS.md`.
- Mission Control follows `prefers-color-scheme` by default, with a Light / Dark / System control (header from `md`, phone section menu below that). The choice is stored in `localStorage` as `vanos-theme`. A blocking head script sets `data-theme` before first paint. Dark mode swaps the existing CSS color tokens; the desktop and phone layouts stay put. Text tokens meet WCAG AA on background, surface, and panel. The GitHub, Notion, and Obsidian panels use those same tokens.
- Read-only GitHub, Notion, and Obsidian panels on Mission Control. Each integration stays off until its env vars are set. Dashboard routes sit behind basic auth and TOTP; agents use `GET /api/v1/github`, `/api/v1/notion`, and `/api/v1/obsidian` with `AGENT_API_TOKEN`. See `ai-support/INTEGRATIONS.md`.
- `VANOS_EDGE_DASHBOARD=true` opts an edge host into also serving the dashboard pages, the API routes those pages call, and static assets (`/_next` and public files). Unset or any other value keeps the strict 404. Ingest, `/api/mcp`, and `/api/v1/health` are unchanged. Use the flag only behind platform auth such as Vercel Authentication.
- Grok Bot assistants can attach Mission Control as a connector at `POST /api/mcp` (stateless Streamable HTTP). Auth is `Authorization: Bearer $AGENT_API_TOKEN`. Tools are read-only (agents, status, costs, recent bot events, connections) plus two creates (dispatch a task, post a bot event). There is no delete tool. Bodies are capped at 64KB and requests are rate-limited per IP.
- Grok Bots can report into Mission Control with `POST /api/bots/ingest` (`Authorization: Bearer $BOTS_INGEST_SECRET`). Events use `botId` or `botName`, `type` (`status` | `result` | `error`), `title`, `body`, and optional `links`, `metadata`, `timestamp`, `dispatchId`, and an idempotency key (`Idempotency-Key` header or `idempotencyKey`).
- Ingest rejects unknown JSON fields, limits the body to 32KB, and rate-limits each bot to 30 requests per minute. A repeated idempotency key returns the original event.
- The dashboard Grok Bots view shows the latest event per bot (including bots that are not configured webhook targets).
- Paste-ready curl lives in `ai-support/GROK-PROMPT.md`. The secret is always the `$BOTS_INGEST_SECRET` placeholder — never commit a real value.

### Changed

- Mission Control is easier to read at a glance. Overview opens with **Needs you**: broken items first, then what needs attention, each with its real time and a link to the section that fixes it; items that are fine fold into one line. The big banner shows only on Overview; other sections get a one-line "N things need you" strip. The Agents tile counts the same agents as the rest of the page. Dates read `2026-10-17 14:05` in your local time (the schedule too), and nothing time-based differs between server and browser any more. Over-budget spend shows red and the real percentage. Dashboard data in alerts gains `at` (ISO time) and `section`; `when` is now optional.
- The menu is grouped (Today, Bots & agents, Money, Growth, Home, System), and each section shows how many open problems it has (red when something is broken). The section is in the address (`/dashboard?s=costs`), so reload, Back and shared links land in the same place. On phones the whole menu scrolls. Connections uses plain labels ("Agents can read", "Agents push data") instead of "MCP ready" and "Ingest only".
- Home / PC: lights, switches, fans and scenes get their own Turn on / Turn off / Activate button with the result next to it; the raw service form moved under **Advanced**. PC layouts ask before they run. Home Assistant and DisplayFusion load independently, so one being down no longer hides the other.
- Grok Bots: a task asks "Send this task to Muddy?" before it goes, and the answer shows next to the button. Bots without a webhook show as idle, not broken. Setup steps, payload examples and raw metadata sit behind **Set up a bot**, **For agents** and **Details**. Status dots have readable labels for screen readers, the active section is marked with `aria-current`, and polling pauses while the tab is hidden.
- The Money panel is in plain English (it was partly Swedish). Amounts in SEK use Swedish formatting, timestamps show as `2026-10-17 14:05` in your time zone, and the ingest example moved behind a collapsed "For agents" section. Money alert texts no longer mention ingest or the seed.
- Legacy heartbeats (`status`, `summary`, `focus`, `alerts`) still ingest when the body does not include event fields.

### Fixed

- **Security:** Logging out now revokes sessions. An authenticated `GET`/`POST /api/auth/logout` stores a new session generation, so every `vanos_session` cookie signed before it, including a copied one, is rejected right away (within 10 seconds on other instances sharing the store) instead of staying valid until it expires. It signs out every browser. An unauthenticated logout only clears that browser's cookie. If storage cannot be written, logout answers `503` and logs `logout` with `revoked: false`. During a storage outage the last known generation is trusted for up to 15 minutes; after that, or after a restart with storage down, the dashboard falls back to Basic auth (TOTP answers `503`) until storage is back. Cookies are now `v3`; existing cookies are rejected once after the upgrade. See `ai-support/SECURITY.md`.
- **Security:** Used TOTP codes and the TOTP attempt counter are kept in the durable store (Upstash, or `.data/bots`) with TTLs matching the code window and `VANOS_TOTP_ATTEMPT_WINDOW_SEC`, so restarting the app no longer lets a code be replayed or resets the attempt limit. Codes are stored as an HMAC, not in the clear. If storage fails, the per-process record and counter still apply.
- **Security:** Dashboard Basic auth always compares both the user name and the password, in constant time over SHA-256 digests, so the response time no longer reveals a correct user name or the length of either value.
- `next build` no longer downloads Google Fonts, which made CI and local builds fail now and then. Syne, Figtree and JetBrains Mono ship with the app (the same latin variable files, from `@fontsource-variable` 5.3.0, SIL OFL 1.1, in `ai-support/src/app/fonts/`) and load through `next/font/local` with the same weights and CSS variables, so the dashboard looks the same and builds offline.
- **Security:** Home Assistant service calls are limited to `HA_ALLOWED_SERVICES` (comma-separated `domain.service`, `domain.*` allowed). The default is lights, switches, fans, media players, input booleans and `scene.turn_on`. Locks, alarms, covers, scripts, automations and `homeassistant.*` now return `403` until you add them, so a leaked agent token can no longer unlock a door.
- **Security:** `/api/displayfusion` no longer skips the dashboard gate. Only a request carrying `DISPLAYFUSION_BRIDGE_SECRET` bypasses it, and that secret can only post run results. Running a command needs the full login, including TOTP. DisplayFusion `args` may hold only plain words, numbers and simple punctuation (no leading `-`, quotes or `$`). The Windows bridge script compares its secret case-sensitively in constant time and quotes each argument; copy the new `VanOS-DisplayFusion-Bridge.ps1` to the PC.
- **Security:** `X-VanOS-Edge` no longer skips the CSRF check on `POST /api/homeassistant`, `/api/bots/dispatch` and `/api/displayfusion`. Caddy adds the header to every request, so a hostile page could otherwise drive those routes through a browser with cached Basic credentials. The Caddy example in `SECURITY.md` now uses `header_up`.
- **Security:** `.backup-to-github.sh` stops before committing when a staged file looks like a secret (`.env*`, keys, certificates, credentials) or a staged line matches an API-key pattern. It uses `gitleaks protect --staged` when installed. The root `.gitignore` now covers `.env.*`, `*.pem`, SSH keys and credential files.

- The dashboard no longer asks for Basic auth (and TOTP, when it is on) on every new window. After a successful login the proxy sets `vanos_session`: `HttpOnly`, `Secure`, `SameSite=Lax`, signed with `VANOS_SESSION_SECRET`, lifetime `VANOS_SESSION_TTL_DAYS` (default 30). A valid cookie skips both prompts on dashboard routes. It is bound to the current password and TOTP secret. `GET` or `POST /api/auth/logout` clears it. Agent tokens, ingest, MCP, and `/api/v1/*` are unchanged. `VANOS_SESSION_TTL_SECONDS` is no longer read.
- The TOTP form can be posted when the browser sends `Origin: null` because of `Referrer-Policy: no-referrer`. That value is accepted only when `Sec-Fetch-Site` is `same-origin`. A null origin with no `Sec-Fetch-Site`, or with any other site value, is still rejected, and a real mismatched origin is still rejected.
- Writes can no longer silently lose data. Every store now does an atomic read-modify-write (a version-checked Lua script on Upstash, a per-key lock locally), so two ingests at once both land. Upstash calls time out after 5s. A write that reaches no durable backend (Upstash down, or no Upstash on Vercel's read-only filesystem) answers `503` with `Retry-After` instead of `ok: true`. Logs of actions that already happened (Home Assistant calls, DisplayFusion runs, dispatches) stay best-effort.
- Ingest data is validated before it is stored. Costs, money and connections use zod schemas: invalid rows in a list are skipped, wrong-typed fields are `400`, lists are capped, and bad rows already in storage are filtered on read, so one malformed write can no longer break the cost or connections panel. Write bodies are capped (64KB; 256KB for `/api/v1/sync`; 32KB per bot event) and checked before parsing. Bot events on `/api/v1/ingest` and `/api/v1/sync` go through the same strict parser and per-bot rate limit as `/api/bots/ingest`. `latestByBot` keeps at most 100 bots. Connections `replace` applies to one ingest only.
- On Vercel the client IP comes from Vercel's `X-Real-IP` / `X-Forwarded-For` instead of `unknown`, so one caller no longer exhausts the rate limit for everyone. With Upstash configured, rate limits are shared across instances; without it, or if it is slow, each instance counts on its own.
- An edge host with `VANOS_EDGE_DASHBOARD=true` but no `DASHBOARD_BASIC_*` answers `503` instead of serving the dashboard publicly, and dashboard read APIs refuse requests without credentials outside development or explicit `public` mode.
- MCP `vanos_create_dispatch` works on the edge host. The three dispatch paths share one function, the bot webhook call times out after 15s, and the callback points at `/api/bots/ingest` with `BOTS_INGEST_SECRET`.
